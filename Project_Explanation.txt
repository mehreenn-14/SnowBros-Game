1. PROJECT OVERVIEW
-------------------
This project is a modern C++ recreation of the classic arcade game "Snow Bros". It is built using the SFML (Simple and Fast Multimedia Library) for rendering, audio, and input handling. The game features a complete player progression system, including login/registration, level-based gameplay, a shop for power-ups, and a persistent leaderboard.

2. CORE TECHNOLOGIES USED
-------------------------
- Language: C++ (Standard 17+)
- Graphics/Audio: SFML 2.5+
- Persistence: File I/O (txt files) for saving user progress, leaderboard data, and level layouts.
- Development Environment: Visual Studio (Windows).

3. ARCHITECTURAL DESIGN & OOP PRINCIPLES (The "How" and "Why")
------------------------------------------------------------
The project is built on solid Object-Oriented Programming principles to ensure scalability and clean code.

A. Abstract Base Classes & Interfaces:
   - Entity.h: An abstract base class for all game objects (Player, Enemy). It defines the "contract" for 'update()' and 'draw()' methods.
   - Screen.h: An abstract base class for all UI states.
   - WHY: This allows the game loop to treat different objects uniformly (Polymorphism).

B. Inheritance Hierarchy:
   - Enemy Hierarchy: 
     Enemy (Base) -> Bottom (Walking) -> Flyng (Flying) -> Tornado (Special).
     Enemy (Base) -> Mogera/Gamakichi (Bosses).
   - Screen Hierarchy:
     Screen (Base) -> MainMenu, GameScreen, ShopScreen, etc.
   - WHY: To reuse code. For example, 'Flyng' inherits movement logic from 'Bottom' but adds flight capabilities.

C. State Pattern (Screen Management):
   - ScreenManager: Handles the transition between different "Screens" (Main Menu -> Character Select -> Game).
   - WHY: It separates the logic of the login system from the gameplay logic, making the code modular.

D. Factory Design Pattern:
   - EnemyFactory: A static class that creates enemies based on string types (e.g., "FLYNG", "TORNADO") provided in level files.
   - WHY: To decouple the creation logic from the GameScreen. Adding a new enemy type only requires updating the factory, not the whole game loop.

E. Operator Overloading:
   - Levels class: Overloads 'operator>>' to read level data directly from text files.
   - WHY: Provides a clean, C++ idiomatic way to handle file parsing.

4. KEY GAMEPLAY SYSTEMS
-----------------------
- Level Manager: Dynamically loads platforms and enemy spawn points from 'levelX.txt' files. This allows for infinite levels without changing code.
- Physics & Collisions: Custom AABB (Axis-Aligned Bounding Box) collision detection between players, enemies, and platforms.
- Power-up System: Uses a timer-based system to handle speed boosts and attack upgrades (Potions/Items).
- Save System: 'progress.txt' and 'users.txt' store encrypted/hashed passwords and user stats (gems, levels, high scores).
